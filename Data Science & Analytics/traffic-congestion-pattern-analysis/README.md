# Smart City Traffic Pattern Analysis Using Hadoop

A Hadoop MapReduce project that performs distributed analysis of urban traffic datasets by aggregating traffic situations based on the hour of the day. The project demonstrates how Apache Hadoop can be used to process large CSV datasets efficiently and identify recurring traffic patterns.

---

## Overview

Traffic congestion is one of the major challenges faced by rapidly growing cities. Understanding when different traffic conditions occur can help city planners, transportation authorities, and researchers make informed decisions.

This project uses the Hadoop MapReduce programming model to process traffic datasets stored in CSV format. Each traffic record is grouped according to:

- Hour of the day
- Traffic situation

The final output shows how frequently each traffic situation occurs during every hour.

Example output:

```
Hour:07 Low      38
Hour:08 High     91
Hour:09 Normal   67
Hour:18 High    104
```

# How It Works

The project follows the standard Hadoop MapReduce workflow.

## Step 1 : Input

The input is a CSV file containing traffic observations.

Example:

```
08:15:20,...,...,...,...,...,...,High
08:20:11,...,...,...,...,...,...,High
09:10:54,...,...,...,...,...,...,Low
```

The project includes two datasets:

- Traffic.csv
- TrafficTwoMonth.csv

---

## Step 2 : Mapping Phase

The Mapper processes one record at a time.

For every record it:

- Splits the CSV row
- Skips the header row
- Extracts the hour from the Time column
- Reads the Traffic Situation column
- Emits:

```
Hour:<hour> <traffic_situation>,1
```

Example:

Input:

```
08:15:20,...,High
```

Mapper Output:

```
Hour:08 High    1
```

---

## Step 3 : Shuffle and Sort

Hadoop automatically groups identical keys.

Before Shuffle

```
Hour:08 High    1
Hour:08 High    1
Hour:08 High    1
Hour:09 Low     1
```

After Shuffle

```
Hour:08 High

1
1
1

Hour:09 Low

1
```

---

## Step 4 : Reducer

The Reducer receives every value belonging to the same key.

Example

Input

```
Hour:08 High

1
1
1
1
```

Reducer Output

```
Hour:08 High 4
```

# Source Code Explanation

---

## TrafficDriver.java

The Driver class is responsible for configuring and executing the Hadoop job.

Responsibilities:

- Creates Hadoop Configuration
- Creates the MapReduce Job
- Registers the Mapper
- Registers the Reducer
- Specifies Output Key type
- Specifies Output Value type
- Reads Input Path
- Reads Output Path
- Executes the job

The Driver is the entry point of the application.

---

## TrafficMapper.java

The Mapper is responsible for processing every line of the input dataset.

### Logic

1. Read one CSV record.
2. Split using commas.
3. Ignore the header.
4. Read the Time field.
5. Read the Traffic Situation field.
6. Extract only the hour.
7. Emit:

```
Hour:<hour> <traffic_situation>,1
```

The implementation uses:

```
Text
```

as the output key and

```
IntWritable
```

as the output value.

---

### Example

Input

```
08:45:12,...,...,...,...,...,...,High
```

Output

```
Hour:08 High 1
```

---

## TrafficReducer.java

The Reducer receives grouped values generated by Hadoop.

Responsibilities

- Receive one key
- Iterate through all values
- Sum every occurrence
- Write final count

Example

Input

```
Hour:08 High

1
1
1
1
```

Output

```
Hour:08 High 4
```

# Installation

Clone the repository

```bash
git clone https://github.com/ArpitMangaraj/smart-city-traffic-pattern-analysis-hadoop.git
```

Move into the project

```bash
cd smart-city-traffic-pattern-analysis-hadoop
```

---

# Compile

```bash
mkdir classes
```

```bash
javac -classpath "$(hadoop classpath)" -d classes *.java
```

Create the JAR

```bash
jar -cvf traffic-analysis.jar -C classes/ .
```

---

# Upload Dataset to HDFS

```bash
hdfs dfs -mkdir -p /traffic/input
```

```bash
hdfs dfs -put Traffic.csv /traffic/input/
```

or

```bash
hdfs dfs -put TrafficTwoMonth.csv /traffic/input/
```

---

# Execute

```bash
hadoop jar traffic-analysis.jar TrafficDriver /traffic/input /traffic/output
```

---

# View Output

```bash
hdfs dfs -cat /traffic/output/part-r-00000
```

# Limitations

Current implementation:

- Processes CSV files only.
- Uses basic comma-separated parsing.
- Aggregates data only by **hour** and **traffic situation**.
- Performs batch processing instead of real-time analytics.
- Does not include visualization or dashboards.
